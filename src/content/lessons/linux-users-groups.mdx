## The one-sentence version

Everything on a Linux computer happens as some <Term id="user-account">user account</Term>, and accounts can join <Term id="user-group">groups</Term> that share access to the same files.

It's like badges in an office. Your own badge opens your own desk drawer. A team badge opens the room your whole team shares. `id` shows you which badges you're carrying:

<MiniTerminal
  scenario="range-permissions"
  commands={["whoami", "id"]}
  task="Type `id` to see your account and the groups it belongs to."
  expect="id"
  success="You're `recruit`, and you're also in the `team` group. That group badge is what lets you read the team's rota."
/>

## Why it matters in security

Attackers don't break into computers so much as into accounts. Every account is a door, and every extra member of a powerful group is another key to a room that matters.

Defenders use accounts as walls, too. A website can run under its own account with access to its own files and nothing else, so if someone takes over the website, they don't get the whole computer. Reviewing who has which accounts, and who is in which groups, is one of the first things a security check does.

## How it actually works

Linux keeps its list of accounts in a file called `/etc/passwd`. Despite the name, it doesn't hold passwords any more. Each line is one account, with its fields split by colons:

    {
      line: 2,

      text: "Name, an x where the password used to be, account number 1000, main group 1000, a description, the home folder, and the program that runs when you sign in.",
    },
    {
      line: 3,
      label: "Kit's account",
      text: "Every person gets their own number and their own home folder.",
    },

/>

The real passwords are kept scrambled in `/etc/shadow`, which only root may read. Groups are listed in `/etc/group`: the line `team:x:1004:kit,recruit` says Kit and you are both in `team`.

When you open a file, the computer checks your account against the file's lock. Are you the owner? Use the owner's letters. If not, are you in the file's group? Use the group's letters. Otherwise, you get the everyone-else letters.

<Term id="root">Root</Term> skips the check entirely. Most people never sign in as root. Instead,
accounts in the `sudo` group can put <Term id="sudo">sudo</Term> in front of one command to run it
as root, and every use is written down in a log.

## Common misconceptions

- **"Root is a person."** Root is an account: the admin account every Linux computer has. Whoever knows its password, or may use sudo, can act as root.
- **"`/etc/passwd` holds everyone's passwords."** It used to. Today it holds an `x`, and the scrambled passwords live in `/etc/shadow`, which only root can read.
- **"Every account belongs to a human."** Many belong to programs, like `syslog`, which writes the logs, or a website's own account. Programs get accounts so they can be kept to their own files.
- **"An account nobody uses is harmless."** A forgotten account with an old password is an unlocked side door. Security reviews look for accounts nobody can explain, and remove them.
