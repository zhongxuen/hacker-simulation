## The one-sentence version

A Linux <Term id="file-system">file system</Term> keeps every file in one big tree of folders, also called <Term id="directory">directories</Term>, that all grow from a single top folder called the <Term id="root-directory">root directory</Term>, written `/`.

Picture a building with one front door. Every floor, room and cupboard is somewhere inside, and you can always give directions from the front door to any of them. Those directions are a <Term id="path">path</Term>.

## Why it matters in security

Knowing where things live is half of any investigation. Linux computers put the same kinds of files in the same places, so a defender, or an attacker, knows where to look first:

| Folder     | What usually lives there                                        |
| ---------- | --------------------------------------------------------------- |
| `/etc`     | Settings for the whole computer, including the list of accounts |
| `/home`    | One folder per person, full of their own files                  |
| `/var/log` | Logs: the computer's diary of what happened                     |
| `/tmp`     | Scratch space that any account can write to                     |
| `/srv`     | Files for the services the computer offers, like a website      |

That last pair matters. Because anyone can write to `/tmp`, intruders often leave tools and notes there. And settings files under `/etc` or `/srv` sometimes hold passwords that shouldn't be there.

## How it actually works

A path that starts with `/` is a **full path**: directions from the front door. `/home/recruit/notes` means "go into home, then recruit, then notes".

A path that doesn't start with `/` is a **relative path**: directions from where you're standing. If you're in `/home/recruit`, then `notes` means the same folder as `/home/recruit/notes`.

A few shortcuts save typing:

- `~` is your <Term id="home-directory">home directory</Term>, your own folder. For the account `recruit`, that's `/home/recruit`.
- `..` means "the folder above this one", and `.` means "this folder".

Three commands do most of the walking. `pwd` prints where you are, `ls` lists what's here, and `cd` moves you somewhere else. `tree` draws a folder and everything inside it:

Some names start with a dot, like `.bashrc`. They're <Term id="hidden-file">hidden files</Term>: a plain `ls` leaves them out to keep things tidy, and `ls -a` shows them.

## Common misconceptions

- **"Linux has drives like C: and D:."** It has one tree. Extra disks, even a USB stick, show up as folders somewhere inside it.
- **"`cd` didn't do anything, so it didn't work."** Most commands that move or change things print nothing when they work. The prompt is your proof: it now shows the new folder.
- **"Two folders with the same name are the same folder."** `/home/recruit/notes` and `/srv/notes` are different places. A name is only unique inside its own folder, which is why full paths matter.
- **"A hidden file is secret."** The dot only keeps it out of a plain listing. Anyone allowed to read the folder can see it with `ls -a` and open it. Protecting a file is the job of its permissions.
