## The one-sentence version

<Term id="least-privilege">Least privilege</Term> means giving every person, program and
<Term id="user-account">account</Term> only the access it needs to do its job, and nothing more.

It's like a hotel key card. Yours opens your room and the gym, not every room in the building. If you lose it, the damage stops at your door.

## Why it matters in security

Attackers rarely break in as the most powerful account. They get in as whoever they can, then try to climb. Every extra power an account has is somewhere they can climb to. Keep each account small, and a break-in stays small.

It helps with honest mistakes too. An account that can't delete the order database can't delete it by accident.

## How it actually works

On Linux, least privilege shows up in a few places:

- **File <Term id="permissions">permissions</Term>.** Each file says who may read, change or run it. A secret gets `600`: its owner, nobody else.
- **Separate accounts for separate jobs.** The bakery's website runs as its own account, `orders`, not as a person's. If the website is broken into, the intruder gets the website's powers, not everyone's.
- **<Term id="root">Root</Term> for single commands only.** Root, the admin account, can do anything. Instead of signing in as root, admins use <Term id="sudo">sudo</Term> to run one command as root when they need to, and every use is written down.

Where the key card analogy breaks down: hotels reset key cards every stay. On computers, access tends to pile up over the years unless someone checks it, so least privilege means reviewing access regularly, not only when it's handed out.

## Try it

This practice computer has one file that's readable by everyone when it shouldn't be. Look at the permissions with `ls -l`, then lock the password file so only you can read it.

Type `id` too: it shows which groups your account belongs to. Groups are how one file can be shared with a team, like the rota in `/srv/team`, without being shared with everyone.

## In practice

In the mission [Reading the machine](/missions/linux-01), a database password sat in a file every account could read. The fix was least privilege: lock the file to the website's own account and its group. Notice that the website had its own account in the first place. That was least privilege working.

## Common misconceptions

- **"Admins should always sign in as root, it's quicker."** It is quicker, including for mistakes and for anyone who takes over the session. Use your own account, and `sudo` for the moments that need it.
- **"Least privilege means we don't trust our colleagues."** It protects colleagues: if their password leaks, the damage is limited, and nobody can blame them for what their account couldn't do.
- **"Extra access in case someone needs it is harmless."** Unused access is still usable by an attacker. Add access when it's needed, and take it away when it isn't.
