## The one-sentence version

Every Linux file carries <Term id="permissions">permissions</Term>: rules that say who may read it, change it, or run it, set separately for the file's owner, its group, and everyone else.

Think of a lock with three keyholes. The owner's key, the group's key and everyone else's key can each open a different mix of doors. `ls -l` shows you the lock:

## Why it matters in security

A password in a file that every account can read isn't a secret any more. Loose permissions are one of the most common weak spots found on real servers, and one of the cheapest to fix.

The idea behind the fix has a name: <Term id="least-privilege">least privilege</Term>. Give each file the tightest lock that still lets the right people do their work. A shopping list can be open. A password file should be locked to its owner.

## How it actually works

Look at `-rw-r--r--` one piece at a time:

    },
    {
      label: "Everyone else",
      value: "r--",

    },
  ]}
/>

Each set can also be written as one number, adding read (4), write (2) and run (1). So `rw-` is 6, `r--` is 4, and `---` is 0. That makes `-rw-r--r--` the same as 644, and `-rw-------` the same as 600. A few numbers come up again and again:

| Number | Letters     | Means                                             |
| ------ | ----------- | ------------------------------------------------- |
| `644`  | `rw-r--r--` | Owner changes it, everyone reads it               |
| `640`  | `rw-r-----` | Owner changes it, the group reads it, nobody else |
| `600`  | `rw-------` | Only the owner, for anything                      |
| `755`  | `rwxr-xr-x` | A folder or program everyone may open or run      |

`chmod` changes the lock. You can give it a number, like `chmod 600 notes.txt`, or letters, like `chmod o-r notes.txt`, which takes read (r) away from others (o).

Only a file's owner may change its lock, plus the admin account, called <Term id="root">root</Term>, which can open every lock on the computer. If a file isn't yours, <Term id="sudo">sudo</Term> runs one command as root, but only for accounts the computer trusts.

## Common misconceptions

- **"`chmod 777` fixes permission problems."** It makes the error go away by letting every account read, change and run the file. Anyone could then rewrite it. Find the one permission that's missing and add only that.
- **"Hiding a file protects it."** A name starting with a dot only keeps it out of a plain `ls`. The lock is what decides who can open it.
- **"Root has to follow the lock too."** Root can read and change any file, whatever its lock says. That's why the admin account is the prize in most attacks, and why sudo is handed out carefully.
- **"Only the owner's letters matter."** The group and everyone-else sets are where most leaks hide. When a file holds a secret, read the last three letters first.
