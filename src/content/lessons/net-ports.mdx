## The one-sentence version

A computer's address gets a message to the right building, and a numbered door, called a <Term id="port">port</Term>, gets it to the right room. The program waiting behind a door to answer it is a <Term id="service">service</Term>.

## Why it matters in security

Every open port is a door someone could knock on. Most are meant to be open: a bakery's website needs its web door. The trouble is the doors nobody remembers opening, running old programs nobody updates.

That's why the first question in most security checks is "which doors are open, and should they be?" Closing a door nobody uses is one of the cheapest fixes there is, because there's nothing left to attack.

## How it actually works

Port numbers go from 1 to 65535. Some numbers are customary, so the same door usually means the same job everywhere:

| Port   | Usually runs                             | In plain words                                                                    |
| ------ | ---------------------------------------- | --------------------------------------------------------------------------------- |
| `22`   | <Term id="ssh">SSH</Term> (Secure Shell) | Typing commands on a computer from far away, with everything scrambled on the way |
| `23`   | <Term id="telnet">Telnet</Term>          | The old way to do the same thing, with nothing scrambled, passwords included      |
| `80`   | A website                                | Web pages, sent as readable text                                                  |
| `443`  | A secure website                         | Web pages, scrambled on the way                                                   |
| `9100` | A printer                                | Print jobs                                                                        |

"Usually" matters. Any program can listen on any door, so a scan's guess is a starting point, not a fact. Some services also greet you with a line of text when you knock, called a <Term id="banner">banner</Term>, which can give away the program's name and version.

Where the door analogy breaks down: a real door is either open or shut, but a port can also be open to some visitors and shut to others. A firewall rule might let the staff network in and turn everyone else away.

## Common misconceptions

- **"An open port means the computer has been hacked."** An open port is a door someone opened on purpose, usually for a good reason. The questions are whether it should be open, to whom, and what's behind it.
- **"Port 80 always means a website."** Usually, not always. Any program can listen on any number. Checking what actually answers, with a tool like `webprobe`, beats trusting the number.
- **"Closing every port is the safest setup."** Then nothing works: no website, no email, no remote fixes. Good security keeps the doors people need, shuts the rest, and limits who can reach each one.
- **"Telnet and SSH are the same thing."** Both let you type commands on a faraway computer, but SSH scrambles everything and telnet sends it as readable text. Anyone watching the network can read a telnet password.
