## The one-sentence version

A <Term id="process">process</Term> is a program that's running right now: each one has a number, belongs to an account, and was started by a command.

A program sitting on the disk is like a recipe in a book. A process is someone actually cooking it, in a kitchen with their name on the door. `ps aux` lists every kitchen that's busy:

## Why it matters in security

Knowing what's running is how you spot what shouldn't be. An unfamiliar name, a program running from the scratch folder `/tmp`, or a familiar program running as the wrong account are classic signs that someone installed something without permission.

The account a process runs as decides what it can touch. A process running as <Term id="root">root</Term> can reach everything, so if it has a weak spot, taking it over means taking over the computer. That's why careful admins run each program under its own limited account.

## How it actually works

Programs live in files, like `/usr/sbin/cron`. Running one creates a process, and the computer gives it the next free number, its PID. It carries the account of whoever started it.

Some processes wait in the background for work. A program that waits for messages from the network, like a web server, is called a <Term id="service">service</Term>. It listens behind a numbered door called a <Term id="port">port</Term>. So every open port a network scan finds is really a process on that computer, waiting for someone to knock.

`ps` on its own shows only the processes in your own terminal. `ps aux` shows everything on the computer. On a real computer, an admin can stop a process by its number, but stopping it only helps if you also find out how it started.

## Common misconceptions

- **"A program and a process are the same thing."** One program can run as many processes at once, like two cooks using the same recipe.
- **"Closing the window stops everything I started."** Services run with no window at all. That's how a web server keeps answering all night.
- **"Only the programs I opened are running."** Every computer runs a crowd of background processes you never started, from logging to timetables.
- **"Stopping a suspicious process fixes the problem."** If whatever started it is still there, it comes back. Defenders find out how it got there before they call it fixed.
