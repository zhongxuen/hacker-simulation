## The one-sentence version

Almost everything in security protects one of three things: keeping information secret, keeping it correct, and keeping it available. Together they're called the <Term id="cia-triad">CIA triad</Term>, from their first letters. It has nothing to do with spies.

Think of a diary. You want it private. You want nobody scribbling in it. And you want it there when you reach for it. Try sorting a real problem:

## Why it matters in security

When something goes wrong, the first question is "what was hurt?" The answer decides what to do. A leaked password list needs every password changed. Tampered prices need the correct ones put back and a check of what else changed. A crashed server needs getting back up, fast.

It also stops you guarding one thing and forgetting the others. A system that keeps secrets perfectly but falls over every Friday isn't secure.

## How it actually works

- <Term id="confidentiality">Confidentiality</Term>: only the right people can read it. File
  permissions, passwords and scrambling protect it.
- <Term id="integrity">Integrity</Term>: nobody can change it without it showing. Permissions on who
  may write, logs of changes, and checks that data hasn't been altered protect it.
- <Term id="availability">Availability</Term>: it works when people need it. Spare copies, a
  <Term id="backup">backup</Term>, and systems that can take a knock protect it.

Some attacks hit more than one. <Term id="ransomware">Ransomware</Term> locks up files, which hurts availability, and often copies them first to threaten a leak, which hurts confidentiality.

Where the diary analogy breaks down: a diary is yours alone. A company's information is shared by many people, so each of the three becomes a question of who, exactly, should be able to read, change and use each thing.

## In practice

Every finding in a Candlewright report says what it puts at risk. "Anyone on this server can read the database password" is confidentiality. "A forgotten computer anyone can log in to" could be all three. You'll see it in the mission [Reading the machine](/missions/linux-01).

## Common misconceptions

- **"Security is only about keeping secrets."** Secrets are one third. A hospital system that's down, or medical records that are wrong, can hurt people more than a leak.
- **"Availability is the IT team's problem, not security's."** Attacks that knock systems over, or lock files for ransom, are security incidents.
- **"Scrambling data fixes everything."** Scrambling protects confidentiality. It doesn't stop someone deleting the files, or the server going down.
